# Размещение на собственном VPS

Приложению нужен только статический HTTP-сервер. Backend, аккаунты ChatGPT, внешняя база и credentials не требуются. Покупка сервера, настройка DNS и реальное развёртывание в этой работе не выполнялись.

## Обычный Nginx

На локальном компьютере или в отдельной build-папке VPS:

```sh
npm ci
npm run build
```

Перенесите **содержимое** `dist/` в выделенную папку, например `/var/www/lapki`. Не перезаписывайте папки других проектов. На сервере Node.js не нужен, если сборка сделана локально.

Отдельный server block (замените `pets.example.org` своим будущим поддоменом):

```nginx
server {
    listen 80;
    server_name pets.example.org;
    root /var/www/lapki;
    index index.html;

    location / { try_files $uri $uri/ =404; }
    location /assets/ {
        try_files $uri =404;
        add_header Cache-Control "public, max-age=31536000, immutable";
    }
    location = /index.html {
        add_header Cache-Control "no-cache";
    }
}
```

У сайта одна HTML-страница, серверный SPA fallback не требуется. Проверьте конфигурацию через `nginx -t` перед reload. Для публичного поддомена настройте HTTPS стандартным способом вашего VPS; операции с сертификатами и DNS здесь не выполняются. Один Nginx может обслуживать три отдельных поддомена с тремя разными `root`, репозитории остаются отдельными.

После размещения проверьте: HTTPS открывается без стороннего аккаунта; восемь фото загружаются; фильтры, избранное после перезагрузки и демо-заявка работают; запросов к внешним API нет. Отдельно проверьте доступ из нужной российской сети. Доступность заранее не гарантируется.

## Контейнер

В репозитории подготовлены `Dockerfile` и `deploy/nginx.conf`:

```sh
docker build -t lapki-demo .
docker run --rm -p 127.0.0.1:8080:80 --name lapki-demo lapki-demo
```

Открыть http://127.0.0.1:8080. Для VPS поставьте существующий reverse proxy с TLS перед портом 8080 или используйте обычное размещение статических файлов выше. Контейнер публикуется только на loopback; внешний домен настраивается отдельно.

Docker-образ в текущем окружении не собирался и не запускался; проверен самостоятельный Vite build. Docker-файлы — переносимая конфигурация для дальнейшей проверки на выбранном сервере.

## Состояние и обновления

Никаких серверных томов не нужно. Анкеты — неизменяемый seed в `src/data/pets.ts`. Избранное и последние 30 подтверждений — localStorage конкретного браузера; их удаление не затрагивает сервер или других посетителей.

Нажмите «Сбросить демо-данные» для чистого сценария. Смена поддомена/схемы HTTP→HTTPS создаёт новый browser origin и отдельное локальное состояние. Контакты и текст заявки в persistent storage не пишутся.

Для обновления измените исходники, повторите проверки и сборку, затем замените файлы только этого сайта. В production используйте полученный `dist/`, а не Vite dev/preview server.
